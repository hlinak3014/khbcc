# KHBCC v2026.10.25-c 수정본

이 ZIP은 기존 6개 페이지·메뉴·카드 배치를 유지한 수정 소스입니다. 배포·도메인 변경·실제 이메일 발송은 수행하지 않았습니다.

## 수정 내용

- S01: KBIA 참여·회원정보 활용은 협의 단계임을 HTML, i18n.js와 content JSON에 동일하게 반영했습니다. JSON 로딩이나 언어 전환으로 확정형 표현이 되돌아가지 않게 했습니다.
- S02/S04: 9개 카드는 실제 #applyForm으로 연결합니다. 선택 분야와 support-area-01~09 식별자를 폼 및 메일 초안에 전달합니다. 이 ID는 해당 지원영역 카드의 식별자이며 미작성 상세 콘텐츠가 있다는 뜻이 아닙니다.
- S03/S05: 필수 항목, 이메일 기본 형식, 문의 분야, 밸류체인·협력형태, 동의를 확인합니다. 메일 초안에는 분야·카드ID·선택 동의 표시·문안버전·초안 생성시각이 포함됩니다. 이는 수신 측에 저장된 동의 증빙이나 법적 처리체계 완결을 뜻하지 않습니다.
- S08/S11: 5개 기능 연구소·장기 이사회는 구성안으로 표시했습니다. 참여기관·인력·예산의 합의 전 상태를 3개 언어에서 맞췄습니다. HUBA 공개자료의 현지 법인 기반과 양국 공동 운영·이 웹사이트의 운영 확정 여부를 구분했습니다.
- S09: EIPP 사업예산을 종료 후 운영비 확약처럼 쓰는 표현을 제거했습니다. 외부공모·서비스 수입은 검토재원이며 확정재원과 구분했습니다.
- 교육: 2025년12월 석사 복수학위 협정과 BME 자체 학사 추진·실제 학생교류를 구분했습니다. 불일치했던 12월10일/11일의 협정 날짜는 이 공개 시제품에서는 월 단위로 표시합니다. 기존 사진 파일명은 식별자로 보존했습니다.
- 기관명: HUBA의 헝가리어 공식명 Magyar Akkumulátor Szövetség를 사용하며, 현행 헝가리 부처명의 Energiaügyi 표기를 Energetikai로 맞췄습니다.

## 현재 기능과 남은 운영 결정

메일 초안 작성만 제공합니다. 이 사이트 자체에 기업 DB, 접수번호, 담당배정·회신·종결 저장, 자동매칭 기능은 없습니다. 메일 프로그램 열기는 발송 또는 수신 성공이 아닙니다. 문의 수신 주소는 기존 platform@khbcc.org를 유지했으며 실제 소유·수신 가능 여부를 검증하지 않았습니다.

기존 개인정보 안내의 처리주체·보유2년 등은 실제 운영기관의 확인이 필요합니다. 이번 코드의 필수 동의 검증을 GDPR 준수 완료로 해석하면 안 됩니다. 처리자·저장 위치·백업·국외이전·처리방침·기관계정·게시권한·운영정책은 별도 확정해야 합니다. 헝가리어 추가 문구는 원어민 감수가 필요합니다.

KBIA 초기18개·확장27개 본문, 상세페이지·필터·접수상태 시스템은 후속 작업으로 남겼습니다. 이번에는 새로운 기능영역이나 메뉴를 추가하지 않았습니다.

관리자는 기존 미리보기/test-repo 모드입니다. 편집 후 변경 JSON ZIP을 내려받아 수동 업로드하는 기능은 있지만, 인증·기관 권한·직접 게시를 연결한 것은 아닙니다.

## 관리자 화면

사이트 주소 뒤에 `/admin` 을 붙여 들어갑니다.


**현재는 미리보기 모드입니다.** 로그인 없이 바로 편집 화면이 뜨고 기존 활동 기록 16건도
그대로 보이지만, **수정한 내용은 저장되지 않습니다.** 화면 구성을 확인하고 보여드리기 위한
상태입니다. 상단에 빨간 표시가 나옵니다.

### 화면 언어

오른쪽 위 **KO / HU / EN** 버튼으로 편집 화면 자체의 언어를 바꿉니다.
메뉴, 입력 칸 이름, 목록의 제목이 모두 해당 언어로 바뀝니다.
기본값은 영어이며, `admin/index.html` 의 `DEFAULT_UI_LANG` 에서 변경할 수 있습니다.

### 화면 사용법

왼쪽에서 **활동 기록**을 누르고, **소식 추가** 버튼을 누른 뒤 칸을 채웁니다.

- **날짜** — 이 값으로 연도가 나뉘고 순서가 정해집니다
- **장소** — 비워도 됩니다
- **사진** — 끌어다 놓으면 올라갑니다. 없으면 비워둡니다
- **관련 링크** — 기사 주소가 있을 때만. `https://` 로 시작해야 합니다
- **한국어 / Magyar / English** — 세 칸 모두 채웁니다

### 실제로 저장되게 하려면

1. <https://decapbridge.com> 가입 (무료 — 사이트 3개, 협업자 10명)
2. 사이트를 만들고 `hlinak3014/khbcc` 저장소를 연결
3. DecapBridge가 알려주는 값으로 `admin/config.yml` 의 `backend:` 부분을 교체
4. `admin/index.html` 에서 `var USE_REAL = false;` 를 `true` 로 변경

이후 편집자를 추가할 때는 DecapBridge 화면에서 이메일로 초대합니다.
초대받은 사람은 GitHub 계정 없이 이메일과 비밀번호로 로그인합니다.

글과 사진은 모두 GitHub 저장소에 저장됩니다. DecapBridge는 로그인만 처리하므로,
이 서비스에 문제가 생겨도 사이트와 데이터는 그대로 남습니다.

## 첫 화면 사진 슬라이드

메인 페이지 오른쪽 사진은 **활동 기록에서 자동으로 가져옵니다.**
사진이 있는 최근 항목 6개가 12초마다 순환하며, 날짜와 제목도 함께 바뀝니다.

활동 기록에 새 소식을 사진과 함께 올리면 첫 화면에도 자동으로 나타납니다.
따로 손댈 것이 없습니다.

바꾸려면 `index.html` 맨 아래 스크립트에서 두 값을 고칩니다.

```
var INTERVAL = 12000;   // 바뀌는 간격 (12000 = 12초)
var MAX = 6;            // 순환할 사진 개수
```

## 본문 문구 편집 (관리자 화면)

관리자 화면(`/admin`)의 **사이트 문구** 메뉴에서 모든 페이지의 본문을 고칠 수 있습니다.
각 문구마다 한국어·헝가리어·영어 칸이 나란히 있으니, 한 언어를 고칠 때 나머지도 함께 확인하세요.

- 실제 파일은 `content/` 폴더의 페이지별 JSON입니다 (`common`, `index`, `research`, `people`, `news`, `apply`, `reports`)
- 칸을 비워두면 기본 문구가 그대로 나옵니다. 실수로 지워도 사이트가 깨지지 않습니다
- 문구 안의 `<br>`, `<b>` 같은 표시는 줄바꿈·굵게 표시입니다. 지우지 말고 그대로 두세요
- **현재는 미리보기 모드**라 저장되지 않습니다. 실제 저장은 DecapBridge 연결 후 가능합니다 (위 "실제로 저장되게 하려면" 참고)

## 관리자 화면에서 고친 내용을 사이트에 반영하기

관리자 화면은 로그인 없이 쓰는 미리보기 방식이라, 고친 내용이 GitHub에 자동으로 저장되지 않습니다.
대신 **수정본을 파일로 내려받아** 올리는 방식으로 반영합니다.

1. `/admin` 에서 문구를 고칩니다
2. 오른쪽 위 **[게시] → [지금 게시]** 를 누릅니다 (이걸 눌러야 수정본이 만들어집니다)
3. 화면 아래 **[수정본 내려받기]** 를 누릅니다. 바뀐 파일 수가 빨간 숫자로 표시됩니다
4. `khbcc-edits-날짜.zip` 이 받아집니다. 압축을 풀면 `content` 폴더(또는 `news.json`)가 나옵니다
5. 그것을 GitHub 저장소 첫 화면에 그대로 올리고 Commit 합니다. 같은 이름의 파일이 덮어써집니다

주의: 내려받기 전에 창을 닫거나 새로고침하면 고친 내용이 사라집니다. 나가려 하면 경고가 뜹니다.

## 주의 — 문구를 HTML에서 직접 고칠 때

`content/` 의 해당 문구가 옛 값으로 남아 덮어쓰고 있는 것입니다.
그 경우 `content/` 의 값도 함께 고쳐야 합니다.
